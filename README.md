# 作業本身審查（階段一，給外部專家）

線上位置：https://fefe9487.github.io/evluate_risk_assessment/

這站給外部專家標 **現用庫 166 筆作業**，規則與內部 LLM-as-judge 階段一相同：只評作業內文，不評該不該掛在某行業。匯出 JSON 可直接拿去跟模型結果比 `coreSet` 與 `itemNotes`。

## 專家怎麼用

1. 用 Chrome / Edge 打開上面網址（不要下載 HTML 後雙擊，資料檔載不進來）。
2. 右上角填**審查人姓名**。
3. 每一筆做兩件事：
   - 勾 **2～4 個**五分鐘核心危害（不要照抄「庫內核心」）。
   - 點有問題的危害情境、改善項目或核心理由，選標籤並用句子說明。沒問題的句子不要標。
4. 定期按「下載進度備份」。全部或告一段落後按「下載審查結果」，把 JSON 寄回。

瀏覽器會自動暫存。換電腦時請用「還原進度」上傳備份檔。

## 標籤（封閉詞表，可多標）

| 標籤 | 意思 |
|------|------|
| 漏提 | 該有的情境或對策沒寫 |
| 空泛 | 寫了但現場做不到 |
| 不符行業 | 對不到本作業名稱／描述（工序錯置），不是「不該掛在某廠」 |
| 寫反 | 把誘發條件或禁令寫成對策，或對策與描述衝突 |
| 跨類複製 | 這句應屬別的危害組 |
| 過長 | 可刪可併的重複句 |

完整規則見 [PHASE1_RUBRIC.md](PHASE1_RUBRIC.md)。引用背景只用來判斷這是泛用卡還是製程綁定卡，不要建議從模板拿掉。

## 匯出格式（與 LLM part 對齊）

審查結果為一個 JSON：

```json
{
  "schema": "ra-task-judge-phase1",
  "phase": 1,
  "annotator": "expert:王小明",
  "tasks": {
    "堆高機駕駛與搬運作業": {
      "taskId": "堆高機駕駛與搬運作業",
      "taskName": "堆高機駕駛與搬運作業",
      "coreSet": ["被撞", "物體倒塌、崩塌"],
      "itemNotes": [
        {
          "groupName": "火災",
          "field": "AvoidItems",
          "index": 0,
          "quote": "原文整句",
          "tags": ["空泛"],
          "problem": "用句子說明缺什麼、為什麼不好、應補什麼方向。"
        }
      ]
    }
  }
}
```

`index` 為 `null` 且 `quote` 為空字串，代表整組缺條、無法對到既有句子。未完成的作業仍會寫進檔案，並列在 `incomplete`。
